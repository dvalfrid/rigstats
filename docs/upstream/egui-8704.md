## The problem (verified 2026-10-12)

- `egui_wgpu::RenderState::create` calls `instance.enumerate_adapters(backends)` and stores the result in `pub available_adapters: Vec<wgpu::Adapter>` for the app's lifetime. This happens for both `WgpuSetup::CreateNew` and `::Existing`.
- On DX12, `wgpu-hal`'s `dx12::Adapter` owns an `ID3D12Device` (`wgpu-hal-29.0.3/src/dx12/mod.rs`, `struct Adapter { device: ID3D12Device, .. }`, created in `dx12/adapter.rs` `expose()`). Every enumerated adapter therefore keeps a device alive.
- Effect on a hybrid laptop: the app holds a context on the dGPU even when rendering on the iGPU, so the dGPU never sleeps. G-Helper and Armoury Crate (Eco mode) kill such processes before switching.
- Evidence: ASUS G14 (Radeon 890M + RTX 5070 Ti), Windows 11, egui/eframe 0.34.3, wgpu 29. With `power_preference: LowPower`, `nvidia-smi` lists `rigstats.exe` and `rigstats-wallpaper.exe` as C+G processes. After emptying `available_adapters`, it lists *no running processes*. G-Helper's log (`%APPDATA%\GHelper\log.txt`) shows `Kill:rigstats` before the fix and none after.
- Still present on egui `main` (checked at `dc282364`, 2026-10-12). No earlier upstream issue; related but different: #2135 (dGPU chosen by default on macOS).

## Proposed upstream change (one PR, small)

Keep real adapters only while selecting; store metadata afterwards.

1. `crates/egui-wgpu/src/lib.rs`:
   - Field (~l.114): `pub available_adapters: Vec<wgpu::Adapter>` → `Vec<wgpu::AdapterInfo>`. Update the doc comment: metadata of all adapters found at start-up; the adapters themselves are dropped because on some backends (DX12) each one holds a device.
   - `RenderState::create` (~l.207–282): keep the local `Vec<wgpu::Adapter>` for `native_adapter_selector` / `request_adapter` / logging as today. Then store `available_adapters.iter().map(|a| a.get_info()).collect()` and let the `Vec<Adapter>` drop at end of scope.
   - `request_adapter` and `describe_adapters` (~l.132, ~l.291) can stay as they are (they take `&[wgpu::Adapter]` and run before the drop).
2. `crates/egui_demo_app/src/backend_panel.rs` (~l.306–315): iterate `AdapterInfo`s. Compare `info != &render_state.adapter.get_info()`. Change `wgpu_adapter_ui` to take `&wgpu::AdapterInfo`, or add a variant that does.
3. Check for other users: `rg available_adapters` across the egui workspace (at `dc282364` only the two files above).
4. Changelog: egui's PR title becomes the changelog line. It is a **breaking change** to a public field, so say so in the PR body and let the maintainer label it.

Alternative if the maintainer prefers no API break: keep the field type and document it, plus add a way to opt out (e.g. drop after selection). Mention it only if asked.

## PR mechanics (egui's rules)

From the PR template / `CONTRIBUTING.md`:
- Fork `emilk/egui`, work on a **branch** (not `main`/`master`), e.g. `egui-wgpu-adapter-info`.
- Keep it small; **short description, no long LLM text**; title = changelog line.
- Run `cargo fmt`, `cargo clippy`, ideally `./scripts/check.sh` (bash; on Windows use Git Bash or WSL). Snapshot tests use git-lfs.
- Open as **draft** until a human has reviewed. Resolve comments once addressed.
- Their "Agents & LLM policy": the human submitter is responsible for the code and text. Daniel reviews everything before it's posted.

Local test of the upstream branch against RIGStats: point the workspace `Cargo.toml` at the fork instead of `third_party/`:

```toml
[patch.crates-io]
egui-wgpu = { git = "https://github.com/dvalfrid/egui", branch = "egui-wgpu-adapter-info" }
```

This only works if the branch is based on the same egui version RIGStats uses (0.34.x). Otherwise test with `egui_demo_app` on the G14 and `nvidia-smi`.

### Draft PR text

> **Title:** `egui-wgpu: don't keep enumerated adapters alive (store AdapterInfo instead)`
>
> * Closes <https://github.com/emilk/egui/issues/8704>
> * [x] I have followed the instructions in the PR template
>
> On DX12, every `wgpu::Adapter` owns a device. Keeping all of them in `RenderState` kept the dGPU of hybrid laptops awake for the app's lifetime. `available_adapters` now holds `wgpu::AdapterInfo`, which covers its only uses (logging, the demo backend panel). This changes the type of a public field.
>
> Verified on a hybrid laptop (Radeon 890M + RTX 5070 Ti): before, the app shows in `nvidia-smi` on the dGPU; after, it doesn't.
